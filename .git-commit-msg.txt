refactor(equipment): переход на model_id — модуль, роуты, формы

Подшаги 3.3.1 – 3.3.2. Единый переход техники на новую модель данных
«модель ТМЦ / экземпляр ТМЦ». Роуты и формы больше не работают
со старыми полями equipment (name, model, manufacturer, category_id,
type_id) — эти данные живут в equipment_models и читаются через JOIN.

МОДУЛЬ БД (3.3.1)

- database/modules/equipment.js — полностью переписан:
  * все SELECT — JOIN equipment_models m ON m.id = e.model_id (INNER);
  * честные имена полей: model_name, model_corporate_id,
    model_manufacturer, category_id, type_id (из модели);
  * addEquipment / updateEquipment — принимают model_id, без name /
    model / manufacturer / category_id / type_id;
  * checkUniqueSerialAndInventory — программная проверка уникальности
    inventory_number / serial_number с понятными ошибками (NULL разрешён);
  * updateEquipment — при assigned → available закрывает активное
    назначение и обнуляет cell_id и workplace_id;
  * getEquipmentCountsByCategory / ByType — считают через JOIN с моделью;
  * moveEquipmentToCellDetailed — отдаёт model_name (было eq.name);
  * getEquipmentWithLocation — фильтр search ищет по m.name,
    m.corporate_id, m.manufacturer, u.full_name, cell.code, wp.name.

РОУТЫ (3.3.2)

- routes/admin.js:
  * renderAdmin — таблица техники: model_name и model_corporate_id;
  * addEquipmentAPI / updateEquipmentAPI — принимают model_id,
    выставляют финальный статус и место, ловят ошибки уникальности;
  * renderAddEquipment / renderEditEquipment — async, подгружают
    {{model_options}}, {{selected_model_id}} и info_* из модели;
  * moveEquipmentAPI — логирует model_name вместо equipment_name;
  * actionNames — добавлены model_create / model_update / model_delete.
